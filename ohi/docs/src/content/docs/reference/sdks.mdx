The ohi SDK lets Scala/JVM, Python and TypeScript applications search publications on
[ohi.dev](https://ohi.dev), inspect their metadata, download selected files and save file selections.

## Installation

<Tabs syncKey="language">
  <TabItem label="Python">
    Python 3.10 or later:

    ```sh
    python -m pip install ohi-sdk
    ```
  </TabItem>
  <TabItem label="TypeScript">
    Node 22 or later, or a browser with Fetch. Browsers need CORS access to the catalog,
    publication and artifact endpoints.

    ```sh
    npm install @neverblink/ohi
    ```
  </TabItem>
  <TabItem label="Scala">
    The Scala modules are built from source and included in the
    [ohi CLI](https://github.com/NeverBlink-OSS/linkml-scala/blob/main/cli/ohi/README.md). They are not published
    separately to Maven Central.
  </TabItem>
</Tabs>

The CLI, the Python package and the TypeScript package share the ohi LinkML release version.

## Quick start

<Tabs syncKey="language">
  <TabItem label="Python">
    ```python
    from ohi import CatalogClient, SearchRequest

    client = CatalogClient()
    page = client.search(SearchRequest(q="sensors", page=1, per_page=10))
    if page.hits:
        publication = client.inspect(page.hits[0].base_url)
        artifact = publication.artifacts[0]
        content = client.get(artifact.url)
    ```
  </TabItem>
  <TabItem label="TypeScript">
    ```typescript
    import { CatalogClient } from "@neverblink/ohi";

    const page = await new CatalogClient().search({ q: "sensors" });
    ```
  </TabItem>
</Tabs>

## Language bindings

| Language | Client | Operation results |
| --- | --- | --- |
| Scala/JVM | `eu.neverblink.ohi.catalog.CatalogClient` in `ohi.catalog.jvm` | Synchronous `SearchResult`, `Publication`, `Array[Byte]` |
| Python | `ohi.CatalogClient` | Synchronous `SearchResult`, `Publication`, `bytes` |
| TypeScript | `CatalogClient` from the package entry point | Promises of `SearchResult`, `Publication`, `Uint8Array` |

## Search

Search uses ohi.dev by default. Each call returns one page. Use `page` to request the next page,
`per_page` to request up to 250 results, and `q="*"` to browse. See the
[search options](https://github.com/NeverBlink-OSS/linkml-scala/blob/main/ohi/model/schema/search-request.yaml)
for filtering, sorting and facets.

When a search reports `search_cutoff: true`, its results or counts may be incomplete.

## Inspect and get

Pass a hit's `base_url` to `inspect`, choose an artifact in the format you need, then pass its
`url` to `get`. `get` returns the file's bytes for your application to save or load.
Dependency files must be selected and retrieved separately.

A known publication or artifact URL can be passed directly to `inspect` or `get`, without
searching first.

## Using another catalog

To use another catalog, supply both `search_url` and `query_by`:

```python
from ohi import CatalogClient, CatalogConfig

client = CatalogClient(CatalogConfig(
    search_url="https://catalog.example/search/collections/packages/documents/search",
    query_by="title,name",
))
```

In TypeScript, pass the fields directly: `new CatalogClient({ search_url, query_by })`.

Replace the example endpoint and indexed fields with your catalog's values. Omitting both selects
ohi.dev. Supplying only one is an error.

## Save and reload file selections

Supply all selected and dependency files with their hashes from publication metadata.

```python
from ohi import ArtifactSelection, Lock, LockedFile, read_lock, write_lock

selected = LockedFile(
    base_url="https://hub.example/releases/energy/2/",
    url="https://files.example/energy.ttl",
    format="owl-turtle",
    sha256="aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
)
lock = Lock(
    format_version=2,
    selections=[ArtifactSelection(base_url=selected.base_url, url=selected.url)],
    files=[selected],
)
write_lock("ohi.lock.json", lock)
saved = read_lock("ohi.lock.json")
```

The URLs and hash are illustrative.
[Version-1 locks](https://github.com/NeverBlink-OSS/linkml-scala/blob/main/ohi/examples/selection.lock.json)
omit hashes and remain supported. See the
[lock schema](https://github.com/NeverBlink-OSS/linkml-scala/blob/main/ohi/model/schema/lock.yaml).

### In each language

| Binding | JSON text | Explicit file path |
| --- | --- | --- |
| Scala/JVM, `eu.neverblink.ohi.model` | `LockJson.decode`, `LockJson.encode` | `LockFiles.read`, `LockFiles.write`, using `java.nio.file.Path` |
| Python, `ohi` | `decode_lock`, `encode_lock` | `read_lock`, `write_lock`, using a string or path-like object |
| TypeScript, `@neverblink/ohi` | `decodeLock`, `encodeLock` | `readLock`, `writeLock` from `@neverblink/ohi/node`, returning promises |

Create the parent directory before writing a lock. Writes replace an existing lock and preserve its
contents on failure. Browser applications use `encodeLock` and `decodeLock` with their own storage.
File operations are available through the TypeScript `/node` entry.

## Metadata

The SDK accepts
[revision 2 publication metadata](https://github.com/NeverBlink-OSS/linkml-scala/blob/main/ohi/model/schema/package.yaml),
illustrated by the synthetic
[Sensors example](https://github.com/NeverBlink-OSS/linkml-scala/blob/main/ohi/examples/sensors-package.json).
Check the publication's licenses and each artifact's format and loading roots. Verify downloaded
bytes against its `size_bytes` and `sha256` if needed. `get` does not perform that check.

## Failures

Catalog failures raise `CatalogException`. Lock validation and file failures raise `LockException`.
Both expose an `.error` record with a `code` and explanatory `message`. See the
[error schemas](https://github.com/NeverBlink-OSS/linkml-scala/tree/main/ohi/model/schema) for
additional fields.

## HTTP behavior

Use the final HTTP(S) URL for publications and files. Requests do not follow redirects or retry.
Set `CatalogConfig.timeout_ms` to override the default 30000 ms timeout.
