## Basic concepts

### Ontology

An ontology defines concepts and relationships in a domain. For example,
[FOAF](https://ohi.dev/foaf/foaf@2014-01-14) describes people, organizations and their relationships.

<OntologyExample />

### Publication

A publication is an **immutable** release of an ontology on ohi.dev. It includes the ontology's
files, metadata and dependencies. Once published, its contents stay unchanged.

Several publications can share the original publisher's version tag. This can happen when the
publisher changes a source file without updating the tag, or when ohi updates a generated file.
ohi adds timestamps to distinguish these publications. For example, FOAF could keep its version tag
through these changes:

Referencing a specific publication ensures you receive identical files each time, even if a newer
publication becomes available.

### Artifact

An artifact is one downloadable ontology file. Its **format** combines a modeling language with a
file syntax.

Take “a person is a type of agent.” In **OWL + Turtle** (`owl-turtle`), it looks like this:

```turtle
foaf:Person a owl:Class ;
    rdfs:subClassOf foaf:Agent .
```

The same statement in **OWL + RDF/XML** (`owl-rdfxml`):

```xml
<owl:Class rdf:about="http://xmlns.com/foaf/0.1/Person">
  <rdfs:subClassOf rdf:resource="http://xmlns.com/foaf/0.1/Agent" />
</owl:Class>
```

The language is still OWL. Only the syntax changed. In **LinkML + YAML** (`linkml-yaml`), you'd write:

```yaml
classes:
  Person:
    is_a: Agent
```

ohi.dev supports OWL in Turtle or RDF/XML, RDFS in Turtle, and LinkML or Apache Ossie in YAML.
Choose an available artifact in a format your tools can read.

### Dependency

A dependency is another ontology that your chosen ontology builds on.
[DCAT](https://ohi.dev/w3c/dcat@3), for example, describes datasets such as a city's bus timetables.
It uses Dublin Core's <code>title</code> property to name them.

dependency so your project can use the same definitions again later.
